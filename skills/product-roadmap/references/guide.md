# 产品路线图规划深度指南

连接产品战略与具体落地计划的长期演化大纲。

## 1. 路线图的核心类型

- **内部开发路线图**: 侧重功能点、技术依赖及 Sprint 优先级。
- **外部客户路线图**: 侧重核心价值交付、大版本功能及市场愿景。
- **战略路线图**: 侧重于 OKR 目标、业务增长重点及市场布局。

## 2. 优先级排序模型

### 常用方法
- **RICE 分值**: Reach (覆盖用户), Impact (影响力), Confidence (信心), Effort (工作量)。
- **Kano 模型**: 基本型需求、期望型需求、兴奋型需求。
- **MoSCoW**: Must-have, Should-have, Could-have, Won't-have。

## 3. 里程碑设定 (Milestones)

- **目标导向**: 每一个里程碑都应解决一个核心业务问题或用户痛点。
- **灵活性**: 长期计划应能适应市场变化, 保持中短期的确定性。

## 4. 沟通与共识

- **利益相关者对齐**: 确保研发、产品、设计及市场部门对目标认知一致。
- **Roadmap 并非死规矩**: 它是一份可以动态调整的演进蓝图。

## 5. 制定步骤

1. **收集输入**: 业务目标、用户反馈、技术债务、竞品动态。
2. **分类池化**: 形成需求池 (Backlog)。
3. **优先级过滤**: 应用排序模型。
4. **可视化排期**: 使用 Gantt 图或看板呈现时间轴。
5. **周期性评审**: 每月或每季度进行修正。

## 6. 路线图检查清单

- [ ] 每个版本是否都有一个明确的核心目标?
- [ ] 是否为不可预见的突发需求预留了 10-20% 的缓冲期?
- [ ] 路线图中的功能是否与当前的公司战略高度一致?
- [ ] 关键路径及其技术依赖关系是否已经识别?
