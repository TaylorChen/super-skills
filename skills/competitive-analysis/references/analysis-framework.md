# 竞品分析框架

## SWOT 分析

SWOT 分析是竞品分析的核心工具,帮助识别优势、劣势、机会和威胁。

### 分析维度

| 维度 | 说明 | 关键问题 |
| --- | --- | --- |
| **Strengths (优势)** | 竞品的强项 | 他们做得好的是什么? |
| **Weaknesses (劣势)** | 竞品的弱点 | 他们的不足在哪里? |
| **Opportunities (机会)** | 市场机会 | 我们可以利用什么机会? |
| **Threats (威胁)** | 潜在威胁 | 有什么风险需要注意? |

### SWOT 分析模板

```markdown
## 竞品: [竞品名称]

### Strengths (优势)
- 用户基数大 (1000万+ DAU)
- 品牌知名度高
- 功能完善,覆盖全场景
- 技术架构先进,性能优秀

### Weaknesses (劣势)
- 界面复杂,学习成本高
- 移动端体验较差
- 定价偏高
- 客户服务响应慢

### Opportunities (机会)
- 竞品未覆盖的细分市场
- 新兴技术应用 (AI、区块链)
- 用户痛点未被解决
- 监管政策变化带来的机会

### Threats (威胁)
- 竞品可能推出类似功能
- 新进入者抢占市场
- 用户需求变化
- 技术迭代风险
```

## 竞品选择

### 竞品分类

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| **直接竞品** | 目标用户、功能高度重合 | 同类型产品 |
| **间接竞品** | 解决相同问题,方式不同 | 替代方案 |
| **潜在竞品** | 可能进入市场的玩家 | 大厂新产品 |

### 选择标准

1. **市场地位:** 选择头部产品和快速增长的产品
2. **用户重合度:** 目标用户群体相似
3. **功能相似度:** 核心功能有重合
4. **学习价值:** 有值得借鉴的地方

**建议数量:** 3-5 个竞品,覆盖不同类型

## 信息收集

### 收集渠道

| 渠道 | 信息类型 | 方法 |
| --- | --- | --- |
| **产品体验** | 功能、交互、性能 | 注册使用,完整体验核心流程 |
| **官方网站** | 产品定位、功能介绍 | 查看官网、博客、文档 |
| **应用商店** | 用户评价、下载量 | App Store、Google Play |
| **社交媒体** | 用户反馈、品牌声量 | 微博、Twitter、Reddit |
| **新闻报道** | 融资、战略、市场表现 | 36氪、TechCrunch |
| **第三方数据** | 流量、用户规模 | SimilarWeb、App Annie |

### 体验清单

```markdown
## 产品体验清单

### 注册登录
- [ ] 注册流程是否顺畅?

- [ ] 核心功能有哪些?

- [ ] 界面设计如何?
- [ ] 操作是否流畅?
- [ ] 有什么体验亮点?
- [ ] 有什么体验问题?

### 性能表现
- [ ] 加载速度如何?
- [ ] 是否有卡顿?
- [ ] 稳定性如何?

### 商业模式
- [ ] 如何盈利?
- [ ] 定价策略?
- [ ] 付费转化路径?
```

## 分析框架

### 波特五力模型

分析行业竞争强度:

1. **现有竞争者:** 竞争激烈程度
2. **潜在进入者:** 进入壁垒高低
3. **替代品威胁:** 替代方案多少
4. **供应商议价能力:** 上游依赖程度
5. **买方议价能力:** 用户转换成本

### 价值链分析

分析竞品在价值链各环节的表现:

```
研发 → 生产 → 营销 → 销售 → 服务
```

每个环节分析:
- 竞品的做法
- 优势和劣势
- 我们的机会

## 最佳实践

✅ **推荐做法:**
- 定期更新竞品分析 (每季度)
- 实际体验产品,不只看资料
- 多维度分析,不只看功能
- 关注用户评价和反馈
- 结合自身优势制定策略

❌ **常见错误:**
- 只分析功能,忽视体验和商业模式
- 只看表面,不深入分析
- 盲目模仿竞品
- 分析后不落地执行
- 忽视间接竞品和潜在威胁
